# How a File Reaches the AI

**Put this video on:** `Build the Portal/01 - See how a file reaches the AI.md`
**Target time:** About 4 minutes
**Goal:** Show the five steps from upload to AI use.

## Show on screen

1. A simple upload page for a fake project.
2. This path: `Upload → Save → Track → Check → AI can use it`.
3. A clean VS Code window and Pi screen.
4. The Client Knowledge Portal Build Brief.

## Script

[ON SCREEN: A simple upload page.]

In this course, we are building a small website called a Client Knowledge Portal.

It has one job. It lets a client add files that may help an AI.

This portal is for one project. The client does not need to pick a project from a list. The portal already knows where the file belongs.

A file moves through five steps.

[ON SCREEN: Show the five-step path.]

First, the client uploads the file.

Second, the system saves it in a private place.

Third, the system makes a database record. This record tells us the file name, where it came from, when it arrived, and its status.

Fourth, a person checks the file.

Fifth, the AI can use the file only after it is approved.

Think of private storage as a locked cabinet. Think of the database as the label on the drawer. The file is inside. The label tells us what it is and what happened to it.

This is the main rule for the whole course:

Uploading a file does not mean the AI should trust it.

[ON SCREEN: Show VS Code.]

I build this in VS Code. VS Code is a program that lets me see my project files, code, and changes in one place. It is like a workbench.

[ON SCREEN: Show Pi.]

Inside VS Code, I use Pi. Pi is an AI helper. It can read my project, change files, and run checks.

Pi helps me build. It does not make every choice. I read the plan. I check the changes. I test the result.

I also use a simple idea from ICM. ICM breaks a big job into small steps. Each step has one job. A person can check the result before moving on.

That is what we are doing here. Uploading is one step. Saving is another. Checking is another. Giving the AI access is the last step.

[ON SCREEN: Open the build brief.]

Before you build, choose a safe test project.

You might use a fake plumbing company. It has a training guide for an AI helper. Mark the guide as fake training data. Do not use a real client file.

Write down who can upload. Write down who can approve. Pick the file types you will allow. Then draw the five steps.

We are not adding chat, smart search, Open Brain, or automatic approval. We will build the small part first and make sure it works.

Start with the file. Track what happens. Let a person check it. Then let the AI use it.
